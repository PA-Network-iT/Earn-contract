Architecture Summary

The protocol is split into a core yield product and a subscription layer. EarnCore holds the liquid asset buffer, mints non-transferable shares through EarnShareToken, tracks user positions as lots, and materializes linear APR through an index. SubscriptionManager decides whether a user is active for EarnCore gate checks and manages paid subscriptions, package passes, sponsor seats, and revenue collection.

All major contracts use proxy-compatible initialization patterns. EarnCore, SubscriptionManager, SubscriptionNFT, and PackagePassNFT inherit UUPS upgrade support and restrict upgrades through an UPGRADER_ROLE check.

The core starts with the subscription gate open because _subscriptionManager == address(0). Once an admin sets a manager, user-facing deposits and withdrawals require an active subscription for the checked user.

EarnCore Functional Behavior

Initialization And Wiring

  • initialize(admin, asset, treasuryWallet, genesisTimestamp, initialAprBps) validates non-zero admin, asset, treasury wallet, and genesis timestamp. It grants all core roles to admin, initializes EIP-712 as PAiT Earn KYC version 1, stores asset and treasury wallet, and creates the first APR version.
  • The initial APR anchor index is IndexLib.ONE_RAY / 10, i.e. 1e26. Tests treat this as the canonical initial index.
  • setShareToken can only be called once by the default admin. It requires non-zero code and requires the share token owner to be EarnCore.
  • setSubscriptionManager activates the subscription gate by storing a non-zero contract address. Before this is set, the gate is intentionally permissive.
  • setKycSigner and initializeKycSigner require a non-zero externally owned signer. Contract signers are rejected by checking signer.code.length != 0.

Deposit Flow

  • Entry points: deposit(uint256,address) and deposit(uint256,address,bytes). Both are nonReentrant and check active subscription on the receiver, not the caller.
  • Caller and receiver must not be blacklisted. Receiver must be non-zero. Amount must be at least the effective minimum deposit.
  • Shares are computed as assets * ONE_RAY / currentIndex. If the computed share amount is zero, the call reverts.
  • KYC is threshold-based per receiver. Cumulative deposits up to 1,000e6 do not require a signature. Once a deposit crosses or exceeds the cap, the receiver must be the caller and a valid deposit-scope authorization must be consumed. The stored cumulative value is capped at the threshold.
  • Deposit assets are split by _treasuryRatioBps. The buffer portion is transferred to EarnCore; the treasury portion is transferred directly to _treasuryWallet.
  • A new lot is stored with principal, shares, entry index, timestamps, and open state. User principal liability and uncapped yield tracking counters are increased. The share token mints shares to the receiver.

Withdrawal Request Flow

  • requestWithdrawal is nonReentrant, subscription-gated for msg.sender, and blocked for blacklisted users or when request pause is enabled.
  • A user can have at most one active, not executed, not cancelled withdrawal request.
  • The request accepts 1 to 50 lot slices. Duplicate lot ids, zero share amounts, non-owned lots, frozen lots, closed lots, and over-withdrawal are rejected.
  • The current index is frozen for the request. For each lot slice, the contract snapshots asset value at the frozen index and snapshots early withdrawal fee if the lot is younger than 365 days.
  • The total requested shares are locked in EarnShareToken. Full-lot withdrawals mark the lot frozen. Partial withdrawals reduce the existing lot in-place and do not create a replacement lot.
  • User principal liability decreases by the requested principal. Frozen withdrawal liability increases by net assets, i.e. assetAmountSnapshot - feeAmountSnapshot.

Cancel Withdrawal Flow

  • cancelWithdrawal requires the caller to be subscribed and not blacklisted. It loads the caller's active request and rejects missing, executed, cancelled, or wrong-owner requests.
  • The request is marked cancelled. Frozen withdrawal liability is reduced by the request net amount.
  • Full frozen lots are thawed. Partial lot slices are restored into the same original lot. Principal liability and yield tracking counters are restored.
  • Previously locked shares are unlocked in EarnShareToken.

Execute Withdrawal Flow

  • executeWithdrawal requires active subscription, non-blacklisted caller, execute pause disabled, valid active request, and 24-hour lock elapsed.
  • The payable amount is the request's net snapshot. Liquidity is checked against the actual asset balance of EarnCore.
  • The request is marked executed before external token transfer. Frozen withdrawal liability is decreased. Fully frozen lots are closed and thawed. Locked shares are burned.
  • The net asset amount is transferred to the request owner. Early withdrawal fees remain in the core balance because only net assets are paid out.

APR And Accounting

  • setApr schedules an APR update 24 hours in the future. It rejects APR above 10,000 bps and rejects scheduling while a future APR version is pending.
  • IndexLib.currentIndex chooses the latest version at or before the target timestamp and linearly materializes index growth from that version's anchor.
  • totals() returns stored principal, frozen withdrawal liability, reported treasury assets, and live yield liability calculated from uncapped shares plus capped yield liability for blacklisted/capped lots.

Compliance And Blacklist

  • setBlacklist(account,true) records the account blacklist timestamp and caps every currently open, uncapped lot at the current index. The lot is moved from live uncapped counters into capped yield liability.
  • setBlacklist(account,false) clears the account-level blacklist timestamp and restores non-frozen open lots back to uncapped yield tracking.
  • Blacklisted users cannot deposit, request, cancel, or execute withdrawals through normal user paths.
  • forceWithdrawBlacklisted(user, lotId) can be called by compliance only. It requires the user to currently be blacklisted, cancels an active request if it contains the target lot, pays at the lot-level or account-level blacklist cap index, closes the lot, burns unlocked shares, and transfers assets to the blacklisted user.

Treasury And Liquidity

  • setTreasuryRatio controls the split applied to future deposits. It cannot exceed 10,000 bps.
  • reportTreasuryAssets is external accounting. It only writes treasuryReportedAssets; it does not move tokens or check balances.
  • transferToTreasury allows TREASURY_MANAGER_ROLE to transfer up to the smaller of core token balance and reported treasury assets, then reduces reported treasury assets.
  • replenishBuffer transfers assets from the treasury manager into the core and reduces reported treasury assets by up to the replenished amount.

SubscriptionManager Functional Behavior

Initialization And State

  • initialize validates non-zero admin, EarnCore, SubscriptionNFT, PackagePassNFT, and payment token. It grants all subscription roles to admin and initializes EIP-712 as PAiT Subscription KYC version 1.
  • hasActiveSubscription(user) returns true only when expiresAt > block.timestamp.
  • Subscriptions store startedAt, expiresAt, and sponsor. Passes store tier id, remaining seats, consumed seats, and purchase timestamp.

First-Time Subscription Purchase

  • buySubscription(partner) is first-purchase only. A user with any existing subscription record, active or expired, must use renewal instead.
  • The requested partner must be non-zero, not the buyer, and actively subscribed.
  • Sponsor resolution consumes one available seat from the partner's pass when possible and records the partner as effective sponsor. If the partner has no pass or no seats, the effective sponsor is address(0).
  • The buyer receives a 365-day subscription and a soulbound SubscriptionNFT.
  • Payment is first pulled into the manager. If the effective sponsor is non-zero, the full subscription price is transferred to that sponsor. If the effective sponsor is zero, the payment remains on the manager as pending revenue for later sweep.

Renewal

  • renewSubscription requires a prior subscription record and requires it to be expired. Early renewal is not allowed.
  • Renewal only updates expiresAt. It preserves startedAt, sponsor, and the existing NFT.
  • Renewal revenue stays on SubscriptionManager until swept.

Package Pass Purchase

  • buyPackagePass(tierId, partner, kycAuthorization) does not require an existing subscription. It always requires a package-pass-scope KYC authorization.
  • The tier must exist, be active, and have a non-zero price. The caller must not already own a pass.
  • First-time buyers may optionally bind a sponsor through the same seat resolver. Existing subscribers preserve their existing sponsor and do not consume another partner seat.
  • Pass purchase grants or extends the buyer to a 20-year bundled subscription. Existing longer subscriptions, including genesis subscriptions at type(uint64).max, are not shortened.
  • The pass NFT is minted with tier and remaining seats. Pass purchase revenue remains on the manager until swept.

Package Pass Upgrade

  • upgradePackagePass(newTierId) requires the caller to have an active subscription and an existing pass.
  • The new tier must exist, be active, be different, and have a higher price. It also cannot reduce the absolute seat allowance below the user's existing absolute allowance.
  • The user pays only the price delta. The remaining seats become newTier.seats - consumedSeats. The NFT tier and remaining seats are updated in-place.

Admin And Treasury Operations

  • addTier, setTier, and removeTier manage tier pricing, seats, active status, and metadata. Tier ids start from 1 and increase monotonically.
  • adminMintGenesisSubscription creates a bootstrap subscription with expiresAt = type(uint64).max, used as a root sponsor.
  • adminGrantPackagePass grants a pass without payment or sponsor binding, but uses the same 20-year subscription extension semantics as paid pass purchase.
  • sweep(token,to,amount) can be called by TREASURY_MANAGER_ROLE, including while the manager is paused. It transfers any ERC-20 token from the manager. Only sweeps of the configured payment token increase totalRevenueSwept.

KYC Authorization

  • Both core deposit KYC and package-pass KYC use the same struct: KycAuthorization(address user,uint8 scope,uint64 expiresAt,uint256 nonce).
  • Core and subscription manager use different EIP-712 domains. The scope separates deposit from package-pass authorization.
  • Each authorization must be non-empty, not expired, not more than one day into the future, match the current per-user nonce, and recover to the configured KYC signer.
  • Nonce increments after successful consumption, preventing replay on the same contract and user.

Token Behavior

  • EarnShareToken is an ERC-20 with 6 decimals. Only its owner, expected to be EarnCore, can mint, burn, lock, and unlock. Transfers between non-zero addresses revert, so shares are non-transferable.
  • Locked shares cannot be burned through the normal unlocked burn path. Withdrawal settlement uses burnLocked, which reduces locked balance first.
  • SubscriptionNFT and PackagePassNFT are deterministic-id, soulbound ERC-721 tokens where tokenId = uint256(uint160(owner)). They reject approval and non-mint/non-burn transfers.
  • Subscription and pass NFTs can only be minted, burned, or updated by their configured manager. Their default admin can change the manager address.

Observed Invariants

  • The APR index should not decrease under configured test scenarios.
  • One user can have many lots but at most one active withdrawal request.
  • Partial withdrawals reduce an existing lot in-place; they do not create fragmented replacement lots.
  • Frozen withdrawal liability is a snapshot and should not grow after request creation.
  • Cancellation restores the original lot state and yield tracking path for the requested slice.
  • Blacklist caps yield for affected lots at the blacklist timestamp, and rehabilitation restores open non-frozen lots to uncapped tracking.
  • Share token total supply changes only through core mint/burn paths; user-to-user share transfers are disabled.
  • Package pass consumed seats are monotonic and are used to make upgrade math independent from later admin edits to old tier storage.
